# 复节奏生产隧道（3 : 4 : 5 节拍门）

一条生产隧道由三组节拍门控制，物体只有在正确的复节奏间隙才能通过。
玩家调整 3 / 4 / 5 三种脉冲的**强弱**与**偏移**，闸门按各自节拍开合；
过早或过晚都会撞门，连续三次失败则隧道停机。

- **Web Audio**：三组不同音色（正弦 / 三角 / 滤波方波）+ 小节地鼓。
- **Canvas**：旋转栅门、节拍环（相位游标与开门弧）、物体位置与撞击特效。
- **同步冻结**：暂停时音乐与闸门画面基于同一虚拟时钟一起冻结，恢复后无错位。

## 运行

ES module 需要通过 HTTP 访问（不要用 `file://` 直接打开）：

```bash
npm run serve        # 等价于 python3 -m http.server 8131
# 浏览器打开 http://localhost:8131/
```

## 玩法

1. 点「启动」开始投入物体，每 2 秒一个，共 12 个。
2. 拖动三组滑块：
   - **强弱**：映射为闸门开启弧的半宽（越强开窗越大）。
   - **偏移**：脉冲中心相对节拍原点的相位（决定开窗落在何时）。
3. 物体到达闸门瞬间若闸门闭合即撞门；连续 3 次撞门立即停机。
4. 空格键或「暂停」可随时冻结；「载入已验证参数」会填入下方求解值。

## 已验证可通过 12 个物体的参数

| 闸门 | 脉冲 | 强弱 strength | 偏移 offset | 最差开门余量 |
| --- | --- | --- | --- | --- |
| 1 | 3 | 0.75 | 0.375 | 0.0625 |
| 2 | 4 | 0.50 | 0.583 | 0.2247 |
| 3 | 5 | 0.75 | 0.000 | 0.0625 |

默认参数（强弱 0.35、偏移 0）会在前三连撞后停机，体现调参必要性。
上述解由 `src/core.js` 的网格搜索求出，并保留正余量（非贴边），对帧抖动稳健。

## 为什么暂停能严格同步

- 全系统只有一个**虚拟时间 `vt`**，碰撞判定、闸门相位、画面都由它推导。
- 音频内部维护锚点 `audioTime = vt + timeOffset`，音符按该映射排到硬件时间轴。
- 暂停：停止推进 `vt`，`suspend()` 音频上下文并立即掐断所有在途音符与挂起闪烁。
- 恢复：用当前硬件时间和冻结的 `vt` 重新计算锚点，再从冻结点重新调度脉冲，
  因此不会因为浏览器在 suspend 期间对 `currentTime` 的处理差异而漂移或重复发声。

## 目录与验证

```
index.html        页面与三组控制条
styles.css        样式
src/core.js       纯逻辑：节奏数学、闸门开合、物体运动、网格搜索
src/audio.js      Web Audio 引擎（虚拟时间锚点 + 暂停冻结）
src/render.js     Canvas 渲染（旋转栅门 / 节拍环 / 物体）
src/main.js       主控：虚拟时钟、RAF 循环、生成与碰撞状态机
test/simulate.mjs 离线仿真：默认失败停机、求解 12 连过、余量与确定性
test/headless.mjs 无头集成：DOM/Audio/Canvas 桩，验证通过、停机、暂停冻结、恢复锚点
```

npm test           # 运行两套 Node 测试
